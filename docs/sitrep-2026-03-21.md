## Issues Found

### Planner wrote to quick-task repo during design phase

The planner's `write_file` tool modified files in `../quick-task/`:
- Deleted the entire `TASKS.md` task list
- Refactored `cli.py` (replaced API imports with lower-level parser calls)

These were reverted. **Root cause:** the planner has unrestricted filesystem write access. It was exploring/prototyping during design, which is not appropriate for the design phase.

**Recommended fixes:**
1. Add `../quick-task/` (or `../`) to `protected_paths` in `genesis.toml` so writes outside the project require human approval
2. Consider removing `write_file` from the planner's tool set entirely — the planner should only produce design docs within the genai project
3. Alternatively, restrict `write_file` to a whitelist of directories (e.g., `docs/designs/`)

### State transition confusion

The planner attempted TODO → IN_PROGRESS (skipping ASSIGNED) on multiple runs despite the tool description documenting valid transitions. It recovered by trying ASSIGNED first on the next call, but this wastes 1-2 LLM calls each time.

**Possible fixes:**
- Have the runner auto-transition to ASSIGNED before handing to the planner
- Return the valid transitions in the error message (already done) and let the LLM self-correct (current behavior, works but wasteful)

### Rate limiting (529s)

Hit Anthropic rate limits (529) during the successful run. The SDK's built-in retry handled it fine. Not a concern unless runs get more frequent.
